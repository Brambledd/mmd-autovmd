# 把 PMX 解析结果发给 LLM，LLM 能"理解"什么 — 实测报告

> 本文档自包含，可直接发给另一个 LLM 会话阅读。所有数据均为实测（2026-11-05，PoPo 仓库，解析工具 `scripts/pmx-info.mjs`）。
> 背景问题：GitHub 上没有专门"帮 LLM 理解 PMX"的项目；现有的 PMX 解析器（如 kanryu/pmx 输出全量 JSON、oguna/MMDFormats 输出 C++ 对象）如果直接把解析产物喂给 LLM，LLM 到底能理解什么？

## 1. 实验设置

- 被测模型：工作区 5 个 PMX 文件（topaz、深空之眼-梵天 及其 3 个变体），PMX 2.0 / UTF-16LE。
- 解析产物分三层，实测体积（以 22764 顶点 / 656 骨 / 519 刚体的 梵天.pmx 为例）：

| 喂给 LLM 的形态 | 实测体积 | ≈ token 数 | 结果 |
|---|---|---|---|
| **结构摘要**（pmx-info.mjs 文本输出，含派生测量） | **520 字符** | ~300 | 轻松放进上下文，信号密度最高 |
| 骨骼级 JSON（全部 656 根骨的名字/位置/标志位） | 335 KB | ~10 万 | 撑掉大半个上下文窗口，绝大部分是 LLM 推理不了的裸浮点 |
| 完整 JSON dump（含顶点/面，kanryu/pmx 式） | **~4.3 MB** | ~140 万 | 超出所有模型窗口；即使塞进去也是"数字噪声灌满上下文"，理解质量反而崩掉 |

信号/噪声比约 **8000 : 1**。结论：**完整 dump 是失败路线，骨骼级 JSON 是浪费路线，结构摘要才是可用形态。**

## 3. 读了这段摘要后，LLM 能得出的结论（真实推断演示）

### 对单个模型（以 topaz 为例），LLM 可以回答六类问题：

1. **这是什么**：名为 topaz 的 MMD 标准人形模型；身高 170cm（21.27u × 8cm/u，MMD 1u≈8cm），腰高 y=8、臂长 52cm / 腿长 86cm → 比例接近正常 8 头身偏少女体型。
2. **能不能直接驱动**：`MPL-core coverage: missing []` → 26 根核心骨全齐，标准 MMD 1-DOF 骨架完整，动画引擎可无条件接管；有左/右足ＩＫ + つま先ＩＫ → 支持脚底钉地、踮脚。
3. **表情系统能力**：66 个顶点变形全为脸部表情（まばたき/ウィンク/にこり/怒り…）→ 可做表情演出；前 18 个未见 あ/い/う/え/お → 口型同步能力需进一步确认。
4. **物理系统**：153 刚体 + 161 关节 → 头发/裙子有物理链；动画时应避开这些骨、交给物理引擎。
5. **资源规模**：2.1 万顶点 / 2.7 万面 / 33 材质 / 9 贴图 → 中高精度模型。
6. **改模差异（跨变体对比，原始 JSON 给不了的高阶理解）**：
   - `short-hair`：656→515 骨（剪掉 141 根发型骨）而刚体数不变 → 换发型未重排物理；
   - `-noik`：IK 全部移除 → **脚部动画必须走 FK 或烘焙，不能钉地**；且身高测量漂移（IK 链变化影响测量语义）；
   - `梵天2`：无 IK、刚体暴涨至 1152/关节 1640、92 个表情且**左右拆分**（`びっくり_R/_L` 等）→ 另一套表情/物理体系的重制版，驱动策略需完全不同。

### 本质上，摘要让 LLM 获得的是四类"可操作语义"：

| 类别 | 例子 |
|---|---|
| 身份与度量 | 名字、身高/比例、坐标系语义（offset vs absolute） |
| 能力清单 | 核心骨覆盖、有无 IK、口型 morph 有无、物理规模 |
| 约束与禁区 | 哪些骨归物理管（不能直接 K 帧）、哪些模型不能钉地 |
| 差异感知 | 同名模型变体间的骨架/物理/表情体系差异 |

## 4. LLM 理解不了什么（摘要也救不了）

- **外观**：贴图是二进制 PNG，材质漫反射色只给粗略色调 → LLM 不知道角色"长什么样"。
- **几何形状**：2 万+ 顶点是浮点数组，任何 LLM 都无法从数字想象出 mesh 形状。
- **骨骼语义盲区**：日文骨名能猜"髪房"是头发链，但"马尾 vs 披发"这类视觉意图只能推测。
- **补救方案**：摘要（文本模态）补全外观需配 1-3 张渲染截图喂视觉模型（仓库已有 `scripts/render-pose.mjs` 可产出）→ **摘要 + 截图才是完整答案**。

## 5. 总结（一段话版本，便于转述）

> 把 PMX 解析结果直接发给 LLM：全量 JSON（~4.3MB/模型）超出一切上下文窗口且几乎全是 LLM 无法推理的浮点噪声；骨骼级 JSON（~335KB）消耗大半窗口但增量信息极少；真正有效的是 **~520 字符的结构摘要 + 派生测量**（身高、骨架覆盖、IK 有无、morph 清单、刚体/关节数、坐标系语义）。它让 LLM 能回答"这模型是谁、多高、骨架全不全、有没有 IK、能不能口型同步、哪些骨不能碰、和别的变体差在哪"。外观理解是摘要的盲区，需渲染截图走视觉模型补全。"解析器 → 语义摘要 → LLM"这一层正是 GitHub 生态的空白点。
